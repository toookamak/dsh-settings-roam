# dsh-settings-roam（设置漫游）

一个 DSH 插件：把某一台机器上配置好的 DSH 设置、已安装插件与 AI 供应商定义推送到云端；在其他机器上拉取并应用，无需重复配置。

- 包名：`@toookamak/dsh-settings-roam`
- 界面显示名：设置漫游
- 当前状态：Git 主流程已有真实远端往返验收；WebDAV 后端与逐项确认预览已实现，尚待真实 WebDAV 服务端演练。
  设置页界面已按宿主设计系统重做，配置项可在界面上直接填写并落盘；
  插件可以在设置页里**检查并更新自己**，不必每次卸载重装；
  读路径双通道交叉校验已接入，「不一致时由用户裁决」的界面尚未做（见演练记录第十节）。

## 它解决什么

用户通常在多台机器上分别运行一份 DSH（例如工作环境与个人环境）。在任一处修改设置、安装插件或配置供应商后，其他机器都需要重复一遍相同操作。

根因不是文件多，而是配置里混着两类东西：**可移植的**（装了哪些插件、配了哪些 provider、主题、人设）和**机器专属的**（监听地址、公开主机名、工作区绝对路径）。本插件的作用就是把这两类显式分开。

## 设计要点

| 要点 | 做法 |
|---|---|
| 分线 | 第一期只做**公共线**（多机共享的配置）；本机专属配置预留为第三期 |
| 范围 | 公共线只覆盖 **DSH 自身与其官方插件**；用户后续自行安装的第三方插件（人设、侧边栏、上下文等）的配置不进公共线，见设计文档 §4.4 |
| 归属表 | 每个配置项标注「公共 / 本机 / 不同步」，第一期就写全三态 |
| 触发 | 纯手动推拉，没有自动同步 |
| 介质 | Git 与 WebDAV 可切换；WebDAV 使用 HTTPS 与 Basic Auth（也可匿名访问） |
| 插件 | **只记名字**，恢复时走官方安装流程重装，不复制插件文件 |
| 装不上时 | 跳过并在报告里列出原因，不中断其余 |
| 密钥 | 永不进云端；provider 的 `apiKeyEnv` 引用名会同步，真密钥不会；凭据交给系统 git / credential helper |
| 可回退 | 应用前自动备份 |

## 不进公共线的三类内容

这三类都有明确后果，设计文档 §4.3 与 §4.4 逐项写明了「包含什么、去掉会怎样」：

| 类别 | 后果 |
|---|---|
| 主题偏好、工具权限预设、默认模型 | 换机后主题、权限档位、默认模型均回到默认值，需逐项手动设置 |
| 第三方插件的配置（含人设） | 插件本身会被重新安装，但其配置内容不会恢复 |
| WebSocket 心跳参数 | 新机器回到默认值，经远程链路使用时可能重新出现连接中断 |

## 更新这个插件本身

装上之后不需要再卸载重装：设置分区里有一行「插件自身」，平时显示当前版本。点「检查并更新」会查询远端；发现新版后立即把 profile 里的依赖改成带提交号的写法（`github:owner/repo#<40 位提交号>`），再交给官方安装流程，所以更新走的是 DSH 自己的账，不会有两份记录。

| 情况 | 界面上怎么说 |
|---|---|
| 本地链接安装 | 「这一份是本地链接安装的，改完代码重启 DSH 即可，不用在这里更新。」——开发时用 `link:`，本来就该热改，不去假装它有版本 |
| 装的是版本号或本地目录 | 「这一份不是从 Git 仓库装的，没有「最新版本」可以比。」 |
| 认不出装的是哪一版 | 仍然允许更新，但话说明白：「有新版本：ca727d9（当前这一版认不出来）」——不编一个「当前版本」出来 |
| 已经是最新 | 「已经是最新版本（ca727d9）。」，不摆一个没用的确认按钮 |

**更新完要重启 DSH**：插件已经加载在内存里，改完依赖只是把新版本装到磁盘上。命令行同样有 `dsh-settings-roam update [--yes]`。

## 设置页里的「设置漫游」一节

这一节由插件自己的浏览器半侧渲染，用宿主的设计系统组件与样式令牌（`@deepseek-ai/dsh-client-ui-primitives`、`--dsw-*`），因此外观与旁边官方分区一致、跟随主题。

页面布局按使用频率排列：本机概况与操作在前；同步目标和范围只需初次设置，放在页面底部。

| 块 | 内容 |
|---|---|
| **本机当前设置** | 一打开就显示当前 profile、供应商、插件配置与技能概况；具体名称可展开核对，多 profile 时在这里选择本次操作的本机来源。它只描述本机现状，不暗示本机与云端相同 |
| **操作** | 导出、导入、与云端对比、拉取和推送。对比只读；拉取和推送先展示预览，再由用户确认。结果紧跟操作区显示 |
| **同步设置（页面底部）** | 选择 Git 或 WebDAV，填写目标地址与认证，并分别设置上传和下载覆盖范围。每个操作都使用这里当前已保存的目标与范围 |

操作完成后，界面会把本机设置概况滚进视野，状态行也会直接说「已导出 N 项」，而不是只说「操作已完成」让人自己去下面找。

**表单不是自动生成的。** 装了 `Config` schema 只让配置项出现在设置服务的描述里，界面上没有任何东西会替插件渲染它（官方设置外壳不给分区内容画任何 chrome），所以这一节里的配置卡是自己接 `ctx.configForms` 画出来的。存储方式选择 git 或 webdav 后，只显示对应的地址和认证字段：

| 字段 | 含义 | 当前是否生效 |
|---|---|---|
| `backendKind` | 存储方式 | **已生效**：填写 `git` 或 `webdav`，界面只显示对应配置 |
| `repoUrl` | 云端仓库地址 | **已生效**：填上之后推送／拉取可用 |
| `branch` | 备份放在哪条分支 | **已生效**：一个仓库可以放多个插件的备份，各占一条分支；留空用 `settings-roam` |
| `webdavUrl` | WebDAV 上级目录地址 | **已生效**：HTTPS 地址；插件会在其下创建并使用 `webdavFolder` 指定的目录 |
| `webdavFolder` | WebDAV 保存目录名 | **已生效**：默认 `dsh-settings`；仅接受单个目录名，目录不存在时会自动创建 |
| `webdavUsername` / `webdavPassword` | WebDAV Basic Auth | **已生效**：明文保存在本机 profile 配置，仅经 HTTPS 发送，不进入同步包；也可留空匿名访问 |
| `uploadPluginIds` | 勾选要上传的配置项 | **已生效**：在本机概况中逐项勾选；默认仅选 `llm-pi-ai`，其中包含供应商和模型设置 |
| `downloadPluginIds` | 勾选要下载并覆盖的配置项 | **已生效**：在本机概况中逐项勾选；确认前展示字段差异并备份本机配置，默认仅选 `llm-pi-ai` |
| `profileName` | 要同步哪个 profile | **已生效**：留空自动判断；多于一个时会明确报错而不是替你猜，界面上同时给出可点的候选名单 |
| `exportRoot` | 导出目录 | **已生效**：推送前在这里落一份可逐项核对的副本 |
| `importRoot` | 导入来源目录 | **已生效**：留空时去导出目录里找最新的一次导出包 |

留空不填不会让插件装不上或报错——插件应当「装好但待配置」，而不是「配置不完整就装不上」。改动在输入框失焦时落盘；保存成功后界面会重新取一次状态，因此填完地址不必手动刷新，「拉取」「推送」当即变为可用。

### 建议操作顺序

1. 选择 Git 或 WebDAV，填写该方式的地址与认证信息。当前选择决定后续推送、拉取和云端比较使用的后端；切换并保存后，下一次操作按新选择连接。
2. 分别勾选要上传、下载覆盖的插件配置 ID。两份名单互相独立，未勾选的插件配置不会被本次选择覆盖。
3. 先查看推送或拉取预览中的文件、字段和技能变更，再确认执行。拉取前会备份本机；云端包校验失败或预览后云端发生变化时，不会继续应用。
4. 查看完成状态和跳过原因。需要迁移到另一台机器时，先在目标机器配置同一后端，再预览拉取。

这里的勾选范围只控制插件配置条目；技能文件和插件安装名单仍按既有同步规则处理。插件名单只记录安装项，不代表会安装；机器专属项和插入指令不会被勾选或覆盖。插件自身更新是单独操作，不属于配置同步。

目前缺少独立的「测试连接」动作，因此 WebDAV 地址或凭据错误会在推送、拉取或云端比较时才显示。产品流程上建议下一步加入连接测试，并在操作区明确显示「当前方式 + 目标地址」，让用户在执行前能再次确认数据目的地。

快照对文本文件的摘要按 LF 统一换行后计算，兼容 Git 在 Windows 工作区的 CRLF 检出；技能等二进制文件仍按原始字节校验。

插件配置选择按本机与云端 `cordis.patch.yml` 中的条目 ID 展示，并在本机概况中提供上传、下载覆盖两个独立勾选框。`llm-pi-ai` 条目包含供应商与模型配置；概况可展开查看配置字段和值，密钥、口令、令牌和凭据字段会在返回界面及同步包前剔除，环境变量引用名（如 `apiKeyEnv`）可保留。设置页 API 只返回剔除凭据后的可同步配置。DSH 自带插件不列入用户安装插件清单；已知机器专属配置和插入指令不能勾选。技能目前仍按原有规则整体同步，插件名单只记录用户安装项，不会安装插件。

状态与动作：

| 控件 | 做什么 |
|---|---|
| 状态行 | 一句话说明当前处于哪种情况：未配置仓库／云端还没有内容／云端有 N 项待拉取／已与本机一致。**读不到本机现状（例如多 profile 还没选）不会被当成「操作失败」**——那是一件要用户做选择的事，整节内容照常显示 |
| 预览块 | 当前机器上有什么：供应商／插件／公共配置项／技能各多少，以及**配置文件路径**。推送／拉取确认区另列本次写入或应用的文件与字段；技能按文件逐项列出。插件名单取不到时显示「—」并说明原因，不显示 0 |
| 可移植的配置 | 把公共条目里的字段列出来（如 `providers.opencode-go.apiKeyEnv`），改完先给「改了哪几项、从什么改到什么」，确认后才写 |
| 跳过项 | 每个没同步成功的项给一句可行动的说明（拿不到 registry、版本不兼容、插件未安装等），不是失败计数 |
| 导出到文件 | **不依赖云端仓库。**一次点击把要备份的东西真实落盘（配置文件、技能、插件名单、清单与人读的概要）。这是第一阶段「能获取到需要的配置」的入口 |
| 导入 | **不依赖云端仓库。**从本程序导出的包（目录里有 `manifest.json`）里回填配置与技能。两段式：先给「会写什么、什么不写回、备份到哪」，确认后才落盘。**只接受本程序导出的包**：清单里的校验值对不上、或包被改动过，会被拒绝而不是尽量写入 |
| 拉取 / 推送 | 两段式：先显示云端摘要校验通过的文件数，再列出涉及的文件、配置字段与技能路径，标明新增、覆盖、移除或保持一致；确认后才真正改动。任一云端文件缺失或摘要不一致就停止；预览后云端再次变化也会要求重新预览。两端独有项目均保留，不做删除 |

「导出到文件」排在第一个，因为它是唯一不需要先有一个远端仓库的动作。

## 交付的范围边界

本插件交付的是**配置同步**，不是**环境复制**。这条边界很重要，避免误解：

| 能做到 | 还做不到 |
|---|---|
| 把 DSH 自身与官方插件的公共配置推到云端、在另一台机器拉取并应用 | 在新机器上自动把插件装好——插件名单会同步，但驱动安装是下一期 |
| 把导出的包在另一台机器上导入回填（**不依赖网络**） | 同步第三方插件（含人设）的配置——第三期 |
| 保证本机的监听地址、主题、权限预设、默认模型**不跟着漂移** | 云端历史版本管理 |
| 应用前自动备份，报告里给出可用的回退路径 | WebDAV 版本历史依赖服务器自身的版本控制功能 |
| 每类跳过原因给出可行动的说明 | |

## 导入只接受本程序导出的包

导入源刻意只认本程序导出的包（目录里有 `manifest.json`），理由有三条：

1. **包本身要可判可信。** 清单里每个文件带 sha256；对不上就拒绝，而不是「尽量写入」。导入这个动作会往用户机器上写文件，属于安全边界，不能靠人眼看一遍。
   更早版本导出的包没有校验值，只降级为「按大小校验」并给出警告——拒绝一份旧包对用户没有帮助。
2. **归属闸门与导出侧同表。** 本机条目（监听地址、主题、权限预设、默认模型）、无 id 的 `insert` 行、不认识的路径一律不写回，并在界面上逐条说明为什么。
3. **写盘前先备份。** 报告里给出可用的回退路径；确认之后才会真正落盘。

**导入不受云端影响。** 没有配置仓库地址也能导入——「换台机器把它弄回来」这件事本就不该要求先有一个远端仓库。

**已在真实远端仓库上试过往返**：推送、换台机器拉取、技能一起带回来，
认证交给系统 git 的 credential helper（本程序不接触任何密码与令牌）。
**仍是本地裸库演练覆盖的盲区**：网络中断、并发冲突（两台机器同时推），这些还没有实测。

界面与本地导出已经过真装载验收：在一台隔离的实例上真发一次 HTTP 请求取数、
真导出一次并去磁盘上确认文件落了出来。「页面上有概述」与「文件确实落盘」是两件事，
前者只看响应体就能骗过，后者必须去磁盘上点一下。

## 曾经的前提验证（已完成）

公共线需要对 `cordis.patch.yml` 做「按 key 抽取 + 合并写回」，这需要一个能处理 DSH 自己的 Loader YAML 方言的解析器。**这曾是整个方案成立的前提。**

**结论：成立，且已实测。** 真实样本（118 行、9 个顶层条目）可被正确切分为公共 1 项与本机 8 项，`!!js` 表达式往返不被求值，合并写回不破坏本机条目。
据此还实测出三条设计文档原先未写明的写路径约束（C1 目标行不存在必须用 insert、C2 警告回调非空即视为写入异常、C3 config 是全量替换而非深合并），
详见设计文档 §7.4 与 [`test/yaml-loader.test.js`](test/yaml-loader.test.js)。

**已知代价**：合并写回会丢失原配置里的注释与手工排版（官方自己的渲染器 `renderConfigDump` 同样如此）。这是有意接受的取舍。

## 一个仓库放多个插件的备份：各占一条分支

Git 备份默认放在仓库的 `settings-roam` 分支上，而且是**孤儿分支**（没有父提交）。WebDAV 会在配置的上级目录下使用 `dsh-settings` 子目录；可以在设置中更换目录名。

| 为什么 | 说明 |
|---|---|
| 不占默认分支 | 同一个私有仓库很可能同时放着别的插件的备份。都往 `main` 上写，两个插件会互相把对方的文件当成「云端多出来的东西」 |
| 用孤儿分支而不是从 main 拉一条 | 从 `main` 拉分支会把别人在那个提交上的文件一起带进我们的工作区，于是「我们的清单」里混进了不属于自己的东西，也让「这个库能不能删」变得说不清 |

分支名可以在设置页改；改成别的名字相当于换一份独立的备份。
